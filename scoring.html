Official scoring log

This page is a separate store from the Replay Feed's alerts. It records the two official-scoring signals — at-bats the official scorer has not ruled on yet (os_ruling_pending_primary / os_ruling_pending_prior, official wording “Official Scorer Ruling Pending”) and scoring changes where the official scorer reclassified a play after the fact (hit ↔ error, out ↔ hit, single ↔ double, …). Each record keeps the exact official wording before and after, the live game state at each observation (score, outs, count, pitch count, pitcher, batter) and a timestamp to the second.

It persists across refreshes in this browser (localStorage, one log per date) and, when the Node server is running, in data/scoring-log-<date>.json via /api/scoring-log. Nothing on this page plays a sound, and a write here can never delay or interrupt an alert. Storage: checking…

Scoring changes 0

Plays whose official classification changed after the fact, with the initial call and the final ruling as the API published them.

Unofficial fan project. Data via the public MLB StatsAPI (statsapi.mlb.com) — pending rulings come from the API's own event-type registry, and scoring changes are detected by snapshotting every completed play's official classification (result.eventType / result.isOut / count.outs / error movements in runners[]) on every capture and diffing it against the previous one. A change can only be logged when its initial call was observed before the change landed; finals are re-read for 30 minutes after they end. This capture loop is independent of the Replay Feed's alert loop: it has its own cadence, its own store and its own error handling, so it cannot delay, reset or silence an alert. See mlb.com/official-information/scoring-changes for MLB's own explanation, and ⚑ Flagged for Review for the verification log. Not affiliated with MLB or MLB Advanced Media.
